ego lite：给 AI 代理一个能并行干活的浏览器，登录态和你的 Chrome 一起继承

发表于 2026-07-26 分类于 开源项目
citrolabs/ego-lite 是一个为「人和 AI 代理共享浏览器」设计的 Chromium 浏览器：每个代理独立 Space 并行跑、复用你 Chrome 的登录态、用 JavaScript 函数代替一连串 CLI 调用，让 Claude Code/Codex/Cursor 真正接管你登录过的那些网站。

你有没有过这种时刻 ——Claude Code 正在帮你抓竞品 LinkedIn 数据，Cursor 又被叫去给一组 X 推文做归档，两个 AI 同时想用你的浏览器跑自动化，结果就是 tab 互相抢、登录态来回掉、验证码连环弹，最后你自己那点搜索请求被挤得没影？更别提每次都得重新登录、装插件、搬 Cookie 的那种烦躁。

有没有可能让 AI 代理直接用你正在用的浏览器，并行地、登录态不掉地跑完一摞活？

这是今天登顶 GitHub Trending 第 2 名、当日新增 36 颗星的 citrolabs/ego-lite 想回答的问题。它用 1 周时间从 1.7k Stars 冲到 2.1k，license 是 MIT，作者把它定位成「给人和 AI 代理同时用的浏览器」。和 Browser-Use、agent-browser、ChatGPT Atlas 都不一样，它不是再做一个 agent 框架，也不是把浏览器塞回 AI 助手，而是把浏览器本身变成共享基建。

项目背景：三种方案都差点意思

过去两年，AI 代理想在浏览器里干点实事，基本就三条路，但每条都卡在一个老问题上：

第一条是「浏览器自动化框架」。 这条路的代表是 Browser-Use 和 Vercel 的 agent-browser。它们的思路是给 agent 一个 Python/Node 库，让 agent 通过 Playwright/Puppeteer 控制一个独立浏览器实例。问题是：要驱动这个浏览器，你得先彻底关掉自己的 Chrome；它不带扩展；要登录就得在脚本里塞凭证；agent 跑起来还可能把你的鼠标抢走。最后你和你自己的浏览器变成两套世界。

第二条是「AI 浏览器」。 ChatGPT Atlas、Perplexity Comet 都是这条路的产物。它们的思路是直接造一个新浏览器，里面塞一个内置的 agent。问题是：这个浏览器只能它自带的 agent 干活 —— 你想让 Claude Code 来接管，得换一套流程；想用 Codex 再接管一遍，又得换一套；登录态更是各自为政。

第三条就是 ego lite 想做的事：「一个浏览器，为你和你带进来的任何 agent 同时设计」。

ego lite 是一个定制过的 Chromium 浏览器。它在首次启动时会问一句「要不要从 Chrome 迁数据」，你回答 yes 之后，你的标签页、保存的密码、扩展、Cookie、登录会话全部会搬过来。从此以后，任何能跑 shell 的 agent（Claude Code、Codex、Cursor、Continue、Gemini CLI、Hermes Agent、OpenCode，甚至你自己写的脚本）都可以通过同一个 ego-browser 技能，把自己的浏览器任务塞进 ego lite 里跑。

核心功能：并行 Space、JS 函数驱动、登录态共享

ego lite 的杀手锏可以拆成三块。

1. 每个 agent 一个独立 Space，不抢你的 tab

传统框架下，agent 跑浏览器任务时会占用你的标签页和焦点。ego lite 引入了「Space」的概念 —— 每一个 agent 任务都在自己的 Space 里跑，标签页、Cookie、登录会话都和你日常浏览的 Space 隔离开。

官方举的例子很直观：

「让 Claude Code 在 10 个 Space 里同时给 10 个 lead 做 enrichment，让 Codex 在另外 5 个 Space 里抓 5 个竞品站点。你自己的标签页一个都不会被打扰。」

这意味着你可以一边继续刷自己的 Slack，一边让 agent 在后台把数据采集跑完。要看 agent 在干嘛，就切到它的 Space；不想看，就彻底无视。所有 tab 都不互相打架，所有焦点都不互相抢占。

2. ego-browser：把浏览器暴露成 in-page JavaScript 函数

这是 ego lite 真正拉开身位的部分。传统的 Playwright/Puppeteer 调用模式是「一次 round trip 干一件事」—— 先 snapshot、然后 fill、然后 click、然后 wait，每一步都是 agent ↔ 浏览器之间的同步阻塞调用。

ego-browser 把浏览器能力直接暴露成 in-page JavaScript 函数（snapshot、fill、click、wait、navigate、capture），让 agent 在浏览器页面里一次性写一段 JS 脚本，把多步操作组合起来跑。结果就是：

  • 复杂工作流完成速度提升到原来的 2.5 倍；
  • 同时每条任务的 token 消耗显著下降（不用每一步都把当前页面状态 round-trip 回 LLM）；
  • 任务越复杂，差距越夸张。

官方 benchmark 对比 Vercel 的 agent-browser，在四个真实浏览器自动化任务上跑出来：

任务类型 agent-browser ego lite 加速比
复杂表单填写 100% ~40% 2.5×
多步骤抓取 100% ~50% 2.0×
跨 iframe 交互 经常失败 100% ∞
登录态持久操作 需重登录 一次登录 N/A

3. 复用 Chrome 登录态 —— 彻底告别 re-auth

这是最戳痛点的一项。你装好 ego lite，迁移完 Chrome 数据之后，你的 agent 第一次想抓 X 推文、抓 LinkedIn profile、抓 Reddit 帖子、抓 Instagram 数据 —— 这些登录后才看得到的内容 ——agent 直接就能用，因为你的会话已经在浏览器里了。

官方说得直白：

「用它作为默认浏览器，你的 AI 代理再也不会卡在验证码、2FA、SSO 跳转里。」

更关键的是这个能力是跨 agent 的：今天 Claude Code 用你的 X 账号做归档，明天 Codex 想接着抓数据，它直接接管 Claude Code 留下的会话就行，不用你重新登录一遍。

另外还有一些值得单独提的能力：

  • Kernel 级自定义的 Snapshot 引擎：ego lite 不是在标准 Chrome 上套一层 JS shim，而是在 Chromium 内核里改了 snapshot 生成逻辑。结果是 snapshot 体积更小、速度更快，并且能稳定处理跨域 iframe、Shadow DOM、Stripe/Salesforce/Intercom 这类第三方 SDK widget—— 这些是其它方案经常翻车的地方。
  • 引用稳定：@N 形式的元素引用在 className 改名之后依然保持不变，agent 不会因为页面改版就把脚本写崩。
  • 本地优先、零数据上传：历史、Cookie、密码、每个页面加载的内容全部存在本机；ego lite 只在首次启动时记录「你是否同意从 Chrome 迁数据」这一个布尔值。

适用场景和限制

ego lite 的设计目标是「登录态 + 并行 + agent 友好」，这让它特别适合以下场景：

  • 社交媒体运营：在 X、LinkedIn、Reddit、Instagram、Threads 上批量跟帖、采集、监控，这些站点都重度依赖登录态和反爬虫指纹，ego lite 因为直接复用你的真实浏览器，绕过了一半的麻烦。
  • 竞品情报抓取：让 Codex 在 5 个 Space 里同时抓 5 个竞品网站的结构化数据，互不打架。
  • 个人 CRM 自动化：让 Claude Code 给一批 lead 批量发个性化消息，登录态不丢，验证码不弹。
  • 本地 MCP 服务对接：ego-browser skill 本身也可以作为一个 MCP server，暴露给任何支持 MCP 的 agent host。

但 ego lite 目前的限制也很清楚，写在它首页：

  • 仅支持 macOS：Apple Silicon 和 Intel 都支持，但 Windows 和 Linux 还在路线图里。Linux 用户如果想用，得等一等或者自己打包。
  • 「可复用 Skills」功能还未上线：官方预告的「把成功操作蒸馏成可复用 skill，下次跑同类型任务快 5 倍」目前还在开发中。
  • 内核改 Chromium 意味着更重的客户端：ego lite 不是 Chrome extension，它是一个完整的浏览器安装包，体积比 Chrome 略小，但首次安装需要迁移数据。
  • 依赖 agent 的 skill 系统：要发挥完整能力，agent 需要支持 /ego-browser 这种 slash command 或者 skills 协议；纯黑盒的 agent（比如只接受 prompt 的在线服务）用不了。

总结

ego lite 不是一个新 agent 框架，也不是又一个 AI 浏览器。它做了一件更基础的事：把浏览器本身变成可以共享的基建。当你和你带进来的 Claude Code、Codex、Cursor、Hermes Agent 一起用同一个 ego lite 时，你们登录一次、并行跑、互不抢 tab。

这种「共享浏览器 + 共享登录态 + 并行 Space」的设计，正好踩中了当下 AI agent 落地最大的那块短板 ——「agent 在登录后的网站里能不能像人一样干活」。如果你一直在为 re-auth、tab 抢占、并行冲突头疼，ego lite 可能是当下最值得一试的方案。
