Claude Cowork 被锁在 SaaS 高墙里？OpenWork 把 AI Agent 工作台彻底开源

发表于 2026-07-31 分类于 AI 开源项目 ， AI Agent
different-ai 开源 OpenWork：把 OpenCode 从命令行变成普通人也能用的桌面端 Agent 工作台，跨工具共享 skills/MCPs/团队市场，自带 SSO 和 Google Workspace 集成，今日 GitHub Trending 第一。

开头：当你妈也想用 AI Agent 时，问题就变了

你有没有遇到过这种” 尴尬”？

你已经把 OpenCode、Claude Code、Codex 用得很熟，写提示词、改代码、跑任务一把梭。但你想让你妈、让你的运营同事、让你那个死活不愿开终端的合伙人，也来做点事 —— 比如把今天 50 张发票按金额排序、给客户邮件分类起草、统一往三个 Slack 频道发通知 —— 他们的第一反应是：

“你告诉我那个 AI 在哪儿打开就行。”

这一步，就卡住了。

市场上确实有过答案：Anthropic 的 Claude Cowork。它把”AI Agent 跑在本地文件上” 这件事包成了一个桌面 App，普通人点开就能用。问题？闭源、SaaS、模型限死、贵。

那有没有一个东西，能把” 命令行猛男用的 OpenCode” 反过来变成” 双击图标就能启动、但底子完全开源、还能团队共享配置” 的 Agent 工作台？

有。different-ai/openwork，今天 GitHub Trending 排第一，2 小时前还在提交。

项目背景：把 OpenCode 从 CLI 拽到桌面上

OpenWork 的作者在 Hacker News 上的原话讲得很干脆：

“我搭了一个家用服务器。我希望我老婆和我都能在上面跑’特权级’的工作流 —— 比如控制 Home Assistant，部署家里的 Web App。OpenCode 太猛，但太工程师。” ——Show HN: OpenWork

翻译过来：底层能力已经有了，但缺一层让非技术人员也能消费这些能力的” 皮”。OpenWork 就是这层皮。

它的关键定位是：

  • 开源：MIT-like 许可，主仓库 different-ai/openwork 已经 18.7k stars，今日 +915 stars。
  • 跨平台：macOS、Windows、Linux 全平台桌面端，Electron + Vite 实现的原生体验。
  • 基座是 OpenCode：所有底层 agent 能力 —— 文件读写、shell 执行、子 agent 调度 —— 继承自 opencode.ai，所以” 为什么这个能干” 这事不用重新发明。
  • MCP-first：不绑定某一个 agent，每一个能挂 MCP 的客户端（Claude Code、Cursor、Codex、OpenCode 自家）都能复用同一套 skills、MCPs、连接配置。
  • 进可攻退可守：可以纯本地跑（文件不出本机），也可以接 OpenWork Cloud 做团队共享 —— 这层是可选付费的 SaaS。

一句话总结：OpenWork = OpenCode 的桌面 GUI + 跨 Agent 复用 + 团队市场。

核心功能：五件事，把 Agent 工作流变成” 团队资产”

OpenWork 我看下来最值得讲清楚的不是 UI 多好看（它确实也还在打磨，作者自己都说 “very alpha, lots of rough edges”），而是它把”AI Agent 个人工具” 变成” 组织能力” 这件事的五个抓手。

1. 桌面客户端：普通人能装、能点、能用

三个平台都有原生安装包。下载 dmg/exe/deb 之后，是真正的桌面 App 而不是浏览器套壳。文件、上下文、提示词都走本地，符合多数企业最在意的” 数据不出本机” 红线。

2. OpenWork MCP：两个接口，让任何 Agent 一键接入

这是我最喜欢的一点。OpenWork 暴露了一个远程 MCP Server：

任何支持 MCP 的客户端都可以加它。挂上之后只暴露两个工具：

  • search_capabilities：看当前账号能用什么 skill、什么插件、什么 MCP 连接。
  • execute_capability：挑选一个去执行。

3. OpenWork Den：管理面 + 企业能力

Den 是组织级的控制平面。功能包括：

  • SSO：企业身份接入，团队成员统一登录。
  • 推理配额：自己接 BYO inference（自带模型供应商），按团队按成员分配额度。
  • 桌面策略：限制能跑哪些本地模型、哪些 App 版本。
  • 成员 / 团队 / 插件市场：把 skill、plugin、MCP 服务打包发布，按组织、按团队、按人授权。

它的定位相当于把”Agent 工作流” 这件事从 chatops 推到了 IGA（identity-governed automation）那一层。

4. Extension Marketplace：让知识像 npm 包一样流转

官方说法是 “publish skills and plugins through marketplaces, then assign them to the organization, a team, or specific people”。你写好的一个 SKILL.md，不再是” 丢群文件大家自己下载”，而是发布到内部 marketplace，指定谁能用。这套体感已经非常接近企业内部的应用商店了。

最关键的是它兼容 Anthropic 兼容的 plugin 协议 —— 你给 Claude Code 写过的能力，可以直接被 OpenWork 挂出去卖 / 分享。

5. 50+ LLM Providers + Google Workspace / Microsoft 365

官网 FAQ 里直白写了：”works with 50+ LLMs from any provider instead of a single vendor, and runs locally”。BYOK（Bring Your Own Key）哲学贯彻到底。同时原生集成 Google Workspace、Microsoft 365，意味着你的” 员工入职流程”” 客户邮件整理”” 日历冲突检测” 这种企业级场景，第一次有了” 开源 + 跨供应商” 的标准实现。

适用场景和限制

适合：

  • 公司内部有自动化流程（财务对账、客户回访、报表汇总），但缺一个” 普通员工能跑 Agent” 的入口。
  • 已经在用 Claude Code / Codex / Cursor 做开发的团队，想把工具和经验沉淀成可复用资产。
  • 对”AI Agent 不能碰内部数据” 有顾虑，优先要本地化部署。
  • 想从单一 LLM 供应商（OpenAI/Anthropic/Google）解锁到 BYOK 模型池。

还不适合：

  • 追求” 开箱即用、零配置” 的非技术团队 —— 目前版本作者自己都承认很 alpha，rough edges 还多。
  • 只做代码生成、不涉及本地文件和工具调用的轻量场景 —— 直接用 Cursor/Claude Code 桌面版就够了。
  • 大型组织的合规 / 审计要求高于 OpenWork Den 当前能力覆盖 —— 目前 Den 还偏向中小企业。

和同类项目的差异：

对手 差异点
Claude Cowork 闭源 + 单供应商 vs OpenWork 开源 + 50+ LLM
Eigent 多 agent workforce vs OpenWork 共享 capability 市场
OpenClaw 聊天驱动 vs OpenWork MCP 驱动（更工程化）
Cursor/Claude Code 单机 IDE 工具 vs OpenWork 团队共享工作台

OpenWork 的护城河就在 “它把 skill/plugin 当成可治理资源” 这一层，这是它和前面那些” 开源 Claude Cowork 套壳” 的最显著区别。

总结：开源的下一战，是把” 个人提示词” 变成” 组织资产”

OpenWork 让我眼前一亮的原因，不是它又一个开源版 Claude Cowork—— 开源套壳已经不少了。真正重要的是：它开始把 AI Agent 工具往” 组织级资产” 的方向做治理。

LLM 不值钱、提示词不稀缺；但” 你公司里谁有权用什么 skill、哪些 MCP 是 QA 过的、谁调用了多少 token”—— 这些是值钱的企业资产，过去只有自建平台能做到。OpenWork 把这条路径做成了开源 + 标准（MCP）+ 可选云服务，第一次让中小团队也能享受这种治理能力。

如果你恰好在做 Agent 工具选型，或者正在头疼” 团队里 OpenCode 用得参差不齐”——different-ai/openwork 值得你花 30 分钟下载来玩一下。
